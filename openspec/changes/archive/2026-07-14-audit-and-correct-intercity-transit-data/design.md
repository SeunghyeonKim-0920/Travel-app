## Context

현재 도시 내 장소 이동은 좌표 간 Haversine 직선거리와 거리 구간별 고정 속도 공식으로 계산됩니다. 일부 보정값은 있으나 모든 도시와 모든 생성 코스의 연속 장소를 대상으로 유지되지 않으며, 장거리 좌표를 8km로 바꾸는 레거시 방어 로직이 실제 오류를 숨깁니다.

## Goals / Non-Goals

**Goals:**

- 지원 도시의 대표 생성 코스에서 실제 장소 간 경로 거리와 이동시간을 검증 가능한 정적 데이터로 유지합니다.
- 검증 데이터가 있으면 런타임 계산보다 우선 적용하고, 출처와 계산 모드를 기록합니다.
- 모든 코스의 연속 장소 쌍, 좌표, 시간값을 자동 감사해 회귀를 차단합니다.

**Non-Goals:**

- 실시간 교통 체증, 운행 중단, 당일 대중교통 시간표를 정적 코스 데이터로 보장하지 않습니다.
- 외부 라우팅 API를 사용자의 브라우저에서 매 이동마다 호출하지 않습니다.
- 장소 체류시간·식사시간·도시간 동선 알고리즘 자체를 이번 변경에서 재설계하지 않습니다.

## Decisions

- **정적 경로 오버라이드 파일**: 개발 시 실제 라우팅 데이터로 산출한 도시·장소 쌍을 별도 패치 파일에 저장하고 `window` 기반 런타임 레지스트리로 노출합니다. 브라우저의 외부 API 의존성과 지연을 피하면서 검증값을 추적할 수 있습니다.
- **도시 내 경로 모드**: 도보로 연결되는 짧은 구간은 보행 경로, 그 외 도시 내 구간은 도로 경로를 기준으로 기록하고 UI의 기존 교통수단 분류를 유지합니다. 기존 명시적 예외는 정적 데이터보다 우선합니다.
- **전수 감사 범위**: 모든 지원 도시의 1~7일 대표 코스와 moderate/relaxed/packed 생성 결과에서 실제 관광 장소가 연속하는 모든 구간을 수집합니다. 좌표가 없거나 synthetic 좌표이면 거리·시간을 승인하지 않습니다.
- **시간 표현**: 기존 `roundTransitMinutes`를 사용해 표시시간은 10분 단위로 반올림하며, 원본 초 단위 경로 거리와 출처는 감사 데이터에 남깁니다.
- **검증 실패 처리**: 데이터가 없는 쌍은 임의의 거리로 표시하지 않고 감사에서 실패시킵니다. 런타임에서는 기존 UI 접근성을 보존하되 `source`를 추정값으로 구분합니다.

## Risks / Trade-offs

- [경로 데이터가 최신 교통상황과 다를 수 있음] → 출처·수집시각·모드를 저장하고 실제 출발 전 지도 링크를 유지합니다.
- [정적 파일 크기 증가] → 대표 코스에서 실제로 생성되는 연속 쌍만 저장하고 정규화된 쌍 키로 중복을 제거합니다.
- [보행 경로와 대중교통 소요시간이 다를 수 있음] → 각 레코드에 mode를 기록하고, 모드가 불명확한 구간은 감사에서 승인하지 않습니다.
- [새 장소 추가 시 경로 데이터 누락] → 코스 커버리지 테스트와 전수 경로 감사 테스트를 CI/배포 전 명령으로 묶습니다.

## Migration Plan

1. 현재 코스에서 연속 장소 쌍과 좌표를 수집합니다.
2. 실제 경로 데이터로 오버라이드 파일을 생성하고 감사 결과를 통과시킵니다.
3. 런타임·루트 HTML·`deploy_live`에 새 파일을 연결합니다.
4. 로컬 Playwright와 정적 테스트를 통과시킨 뒤 Surge에 배포합니다.
5. 배포 후 대표 도시의 코스와 지도를 재확인합니다. 문제 발생 시 새 패치 파일과 HTML 버전만 이전 커밋으로 되돌립니다.

## Open Questions

- 실시간 교통량과 당일 운행 변경은 정적 경로 데이터의 범위를 벗어나므로, 현재는 출발 전 지도 확인 링크를 계속 제공합니다.
