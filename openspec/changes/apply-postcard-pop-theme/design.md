## Context

The app is a static multi-view HTML/CSS/JavaScript application whose functional views share one large stylesheet. Postcard Pop was validated in an isolated preview and is now the selected production direction. Existing user data, generated itinerary markup, localization, mobile navigation, sharing, maps, and dialogs must continue to work without structural rewrites.

## Goals / Non-Goals

**Goals:**
- Apply a recognizable Postcard Pop visual system across every production view.
- Introduce the approved travel-arrival photograph as the dashboard hero background.
- Preserve readable contrast, focus states, touch targets, and responsive behavior.
- Keep root and `deploy_live` byte-equivalent for all affected production files.

**Non-Goals:**
- Rewriting view markup generated by JavaScript.
- Changing itinerary, route, companion, profile, feedback, or persistence behavior.
- Removing the design comparison gallery.

## Decisions

1. Add a `theme-postcard-pop` class to the body and place a scoped production-theme layer at the end of `style.css`. This keeps the change reversible and avoids destabilizing existing component layout rules.
2. Override shared design tokens first, then style the high-value structural surfaces: header, navigation, hero, forms, buttons, cards, timelines, chat, maps, and modals. Existing component classes remain the behavioral contract.
3. Use `hero-arrival-v2.jpg` as a local hero background with a solid translucent overlay. Local storage avoids third-party image availability and the focal point is adjusted for portrait mobile.
4. Keep the existing fixed bottom navigation on mobile. Postcard borders and colors change, but dimensions and labels remain stable.
5. Bump the production build and stylesheet query version so the service worker and browser caches load the selected theme immediately.

## Risks / Trade-offs

- [The appended theme layer can miss dynamically generated selectors] -> Cover shared card, form, modal, timeline, route, room, feedback, and chat families and verify all five core views in Playwright.
- [Heavy borders can reduce usable mobile width] -> Use `box-sizing`, responsive one-pixel mobile borders where needed, and test portrait and landscape overflow.
- [Hero photography can reduce localized text contrast] -> Use a consistent dark translucent overlay and verify heading/button contrast visually.
- [Cached CSS can preserve the old theme] -> Bump the build identifier and all mirrored HTML references before deployment.
